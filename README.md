# 光伏电站运行维护管理平台

面向电站台账、组串阵列、逆变器、汇流箱、跟踪支架、组件清洗、告警处置与发电结算的一体化光伏电站运行维护工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `pv-plant-ops:entries` 这一项，或调用 `resetModule(模块)`。

## 缺陷消缺闭环规则

缺陷闭环是一条独立于通用流转的领域链路，规则集中在 `frontend/src/api/defect.ts`，
页面（列表、详情面板）与「另存闭环册子」共用同一个 `viewDefect` 口径，不存在两套算法：

- **状态单向流转**：待派发 → 消缺中 → 待验收 → 已闭环，只能走到紧邻的下一环，不能跳环、回环；
  已闭环是终态，消缺措施、要求完成日、闭环结论一律锁定。
- **超期口径**：在办缺陷 = 未闭环且要求完成日早于今天；闭环瞬间把结论固化为「闭环超期」快照，
  之后不再随日期或算法变化。历史已闭环但没有快照字段的老记录保持原结论（按时闭环），不翻旧账；
  要求完成日缺失的老记录先按未超期处理，补录后自动纳入。
- **事务落库**：状态、超期标记、实际完成时间、备件待领用台账在一次 `commit` 里整体落
  localStorage，先落库成功才换内存；落库抛错则整笔回滚。连续两次「确认闭环」幂等，只计一次。
- **权限**：只有缺陷「责任班组」的班长能改要求完成日（页面右上角可切换演示身份）。
- **台账回写**：闭环登记的领用备件写入 `spare-ledger`（同备件合并数量），备品备件页的
  「在办缺陷数」与缺陷页共用 `activeDefectCount()`，两处始终对得上。
- **补录**：要求完成日按发现方式给的时限补齐（告警/在线监测 3 天、巡视 7 天、检修 15 天、
  未知方式 7 天，发现日期缺失走兜底基准）；逐条独立提交，中途失败或关掉页面，下次只补仍缺失
  的记录，接着往下补、不重复。

领域规则有一份 Node 端到端验证脚本 `frontend/test-domain.ts`（不进生产构建）。
